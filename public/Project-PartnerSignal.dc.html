PartnerSignal

A partner prospecting, qualification and follow-up workspace for professional-services teams. It finds the reseller partner worth calling, turns rough call notes into a qualified opportunity with AI, routes the work to the right technical specialist, and keeps every follow-up on time.

The project question: what would a professional-services associate need to start better partner conversations every day, qualify them honestly, and follow through, using AI to do the busywork without handing it the judgement?

01

The role, translated into software

Every screen maps to a part of the job.

I started from the day-to-day responsibilities of an early-career professional-services associate and built one working feature for each, so the project shows how I would actually do the work, not only that I can write code.

ResponsibilityWhat PartnerSignal does
Reach out to reseller partnersA signal feed built from renewal calendars, end-of-support dates, purchase patterns and cloud-marketplace activity, plus a whitespace map of where each partner sells product but attaches no services.
Uncover and qualify customer needsCapture a call structures rough notes into challenges, practice fit and BANT qualification, quoting the notes as evidence. Stage gates stop an opportunity advancing without that evidence.
Work with sales and technical specialistsRouting suggests the least-loaded specialist in the practice and generates a handoff brief: context, challenge, proposed scope, open questions and the ask.
Use AI and CRM data to personalize outreachDrafts for introductions, follow-ups, specialist meetings and re-engagement, each explaining which record every line relies on. A person edits, checks and sends.
Follow through and keep an accurate pipelineA ranked daily queue, follow-up dates set automatically from each stage's cadence, a drag-and-drop pipeline, win/loss reasons, reports and a CRM-style CSV export.
Learn to discuss AI and services with partnersA playbook per practice: what to listen for, what to ask, what to offer, and AI use cases worth raising.
02

The workspace

Start the day with a ranked list, not a blank CRM.

The Today view ranks overdue follow-ups, stalled deals, opportunities waiting for a specialist and fresh signals into one queue. Each row lists the reasons it is there, and the week's touch goal sits above it.

03

AI with a person in the loop

The model does the structuring. The associate makes the call.

Call capture and outreach drafting use the Claude API with structured outputs validated against Pydantic models. Without an API key, or if a call fails or hits the demo limit, the same endpoints answer from a deterministic rules engine that returns the same shape, and the interface says which one ran.

Guard rails

Evidence, not invention

  • Quotes must be verbatim; anything not discussed stays unknown and becomes a follow-up question.
  • Prompts carry the service catalog and BANT definitions, and forbid invented names, numbers or dates.
  • Refusals, truncated responses and API errors fall back to the rules engine instead of failing.
  • Per-visitor and daily limits on live model calls.

Outreach

Drafts that explain themselves

Each draft lists which record every personalized line came from. Approving it requires ticking a review checklist, edits are recorded, and nothing is ever sent by the system: the associate sends it from their own mail client and the touch is logged.

04

Decision support

A priority score anyone can argue with.

Every opportunity carries a 0–100 priority score made of four capped parts. The breakdown lists the reason for every point, so a manager or specialist can see why something is at the top and correct the record if it is wrong. It ranks attention; it is not a probability of winning, and the interface says so.

ComponentMaxDriven by
Service fit25Signal strength, the customer's own words, whether the partner has resold this practice before
Qualification30BANT evidence: budget, authority, need and timeline, 7.5 points each at their strongest level
Momentum20Days since the last touch, minus a penalty for stalling in a stage
Urgency25Overdue or upcoming follow-ups and customer deadlines within 120 days
05

Engineering

Built like a small production service.

One catalog module defines the practices, services, stages and playbooks, and the scoring rules, AI prompts and interface all read from it. Business rules live in a service layer with their own tests; the HTTP layer only validates input and maps errors.

API

FastAPI and SQLAlchemy

Typed request models, stage-gate conflicts returned as HTTP 409 with a to-do list, relative-date seeding so the demo always has something due, and security headers.

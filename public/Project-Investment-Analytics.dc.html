01 / Project question

How does the way we invest change the return and risk we take?

The goal is to compare four ways of allocating the same investment across Canadian stocks: Growth, Income, Balanced and Low Volatility. We want to understand what each allocation earned historically, how much it could lose along the way, and how its results compare with the Canadian equity benchmark, XIC.

To answer that question, I built a Python and SQL pipeline that validates market data, applies portfolio rules and trading costs, calculates performance, and simulates five-year outcomes from completed history.

What the reader can assess: which allocation best matches a stated objective and tolerance for losses, how sensitive that conclusion is to modeling assumptions, and whether the calculations and validation are reliable enough to support further research.

02 / Portfolio design

Eight securities, four allocation policies.

Growth, Income and Balanced use manually specified target weights. Low volatility uses inverse sample volatility estimated from the first 252 return observations, then freezes those targets. All portfolios are long-only equities; Balanced has no bond allocation, and Income does not separately model dividend cash payments.

Why XIC?

XIC.TO, the iShares Core S&P/TSX Capped Composite ETF, supplies a broad Canadian equity reference in the same currency. It answers whether these selected allocations improved on holding the Canadian market. The portfolios' sector concentrations differ from XIC, so return differences combine market exposure and security selection; they are not isolated manager skill.

VFV could be a useful secondary opportunity-cost comparison with US equities. It is not included in this experiment. A sector-matched benchmark would further help distinguish allocation effects from security selection.

03 / Data pipeline

A traceable path from inputs to outputs.

  1. Extract

    Read prices, target holdings and the security master. Download adjusted prices through yfinance or reuse a checksum-verified frozen CSV.

  2. Clean and validate

    Parse dates and numbers, count exact duplicates, reject conflicting records and missing prices, and verify the security universe and target weights.

  3. Calculate

    Pandas and NumPy calculate asset returns and rolling statistics, then simulate portfolio value, drifting allocations and transaction costs.

  4. Simulate scenarios

    Resample completed return blocks into five-year paths without accessing post-projection data.

  5. Compare downside

    Measure losses of principal, maximum drawdowns and paired strategy differences across shared simulated market paths.

  6. Publish the data mart

    Replace the SQLite snapshot atomically after integrity checks. Preserve successful run history and reconcile positions to portfolio NAV.

Inspect the implemented SQL queries

CTEs and ROW_NUMBER select month-end NAV; LAG computes compounded monthly and 20-session returns; DENSE_RANK ranks assets by trailing volatility. Sector reporting joins positions to the security dimension. The first monthly return is undefined without a preceding month-end.

-- Latest allocations, with sector names obtained from the security dimension.
CREATE VIEW latest_sector_exposure AS
WITH latest AS (SELECT MAX(date) AS date FROM portfolio_positions)
SELECT p.portfolio_id, s.sector, SUM(p.market_value) AS market_value,
       SUM(p.weight) AS weight
FROM portfolio_positions p
JOIN securities s ON s.ticker = p.ticker
JOIN latest l ON l.date = p.date
GROUP BY p.portfolio_id, s.sector;

-- Compound monthly returns from month-end NAV using a window function.
CREATE VIEW monthly_portfolio_returns AS
WITH ranked AS (
 SELECT *, SUBSTR(date, 1, 7) AS month,
 ROW_NUMBER() OVER (PARTITION BY portfolio_id, SUBSTR(date, 1, 7) ORDER BY date DESC) AS rn
 FROM portfolio_daily_summary
), endpoints AS (
 SELECT portfolio_id, month, nav FROM ranked WHERE rn = 1
)
SELECT portfolio_id, month, nav,
 nav / LAG(nav) OVER (PARTITION BY portfolio_id ORDER BY month) - 1 AS monthly_return
FROM endpoints;

-- Daily cross-sectional ranking by trailing annualized volatility.
CREATE VIEW volatility_ranking AS
SELECT date, ticker, rolling_volatility_20,
 DENSE_RANK() OVER (PARTITION BY date ORDER BY rolling_volatility_20) AS volatility_rank
FROM security_daily_analytics WHERE rolling_volatility_20 IS NOT NULL;

CREATE VIEW rolling_portfolio_returns AS
SELECT date, portfolio_id,
 nav / LAG(nav, 20) OVER (PARTITION BY portfolio_id ORDER BY date) - 1 AS return_20_sessions
FROM portfolio_daily_summary;

04 / Financial calculations

Make the accounting conventions explicit.

Historical adjusted closes approximate dividend-reinvested returns. Position quantities are adjusted-price accounting units, not actual broker share balances. Portfolios start at the calibration close; the first measured return is the following trading session.

Daily asset return

rt = Pt / Pt−1 − 1

Today's adjusted close divided by yesterday's, minus one. This makes differently priced stocks comparable.

Portfolio return

rp,t = ∑ wi,t−1 ri,t

Weight each asset's return by its previous-close portfolio weight. Using end-of-day weights would mix today's price movement into the allocation that supposedly earned it.

Annualized compound return

CAGR = (Vend / Vstart)252/N − 1

Converts growth over N observed daily returns into an annualized compound rate. V is net portfolio value.

Volatility and Sharpe

σannual = s(r) √252
Sharpe = mean(r − rf,daily) / s(r) × √252

s(r) is sample daily standard deviation. The fixed 3% annual risk-free assumption is converted to a daily compound rate. Zero volatility gives an undefined Sharpe ratio.

Maximum drawdown

Dt = Vt / max(V0, …, Vt) − 1

Maximum drawdown is the most negative D. Including starting capital ensures an immediate loss is counted.

Trading costs

Cost = Vbefore cost × ∑ |wtarget − wdrifted| × 0.001

Ten basis points on total absolute traded notional, counting both purchases and sales. Costs reduce NAV before the next return is calculated.

Rebalance timing: weights drift daily and reset at the close of the first observed session of each month. XIC is held without rebalancing. Initial entry costs, taxes and additional market impact are excluded. The recorded costs are cumulative cash charges, not the full compounded performance drag.

05 / Backtesting & validation

Tests target errors that would change the conclusion.

Calculation and chronology

  • A 10% loss followed by a 10% gain compounds to a 1% loss.
  • Initial losses count toward drawdown.
  • Portfolio returns use previous-close weights.
  • Trading costs reduce the final portfolio value.
  • Changing future prices leaves initial low-volatility weights unchanged.
  • Scenario dates begin only after the last completed backtest date.

Data and publication

  • Reject negative, missing and infinite price fields.
  • Reject conflicting duplicates and unknown holdings.
  • Count and remove exact duplicate records.
  • Reconcile position weights and values to NAV.
  • Reject incomplete ticker-date coverage.
  • Preserve the previous database when publication fails.

Backtesting and controls against look-ahead bias

A backtest replays historical prices under declared portfolio rules. Look-ahead bias occurs when a decision uses information that was only available later. We guard against that in return timing, weight calibration and scenario inputs. These controls do not prove the entire research design is bias-free.

At each historical return date, the portfolio uses the weights held at the previous close; it cannot use that day's market move to decide the weights that earned it. Low Volatility weights are calibrated once from only the initial 252 sessions, then frozen. Monthly rebalances are booked after the day's return and cost, affecting only future days. The five-year scenario engine starts after the final historical date and resamples only completed net-return history.

Remaining bias: the security universe and manual allocation policies were selected retrospectively. This creates selection and survivorship risk even when the calculations use correctly timed weights. Adjusted prices are a current historical snapshot, not a point-in-time archive. Five-year scenarios use all data available at August 2026 and are never fed back into earlier backtest decisions. The five-year scenario ranges have not been validated against unseen five-year outcomes.

The automated suite has 19 passing cases, including checks that paired downside differs from subtracting separate percentiles and that tail-loss metrics reconcile on known loss paths. A GitHub Actions workflow is defined for tests, a synthetic pipeline run and notebook generation. Local execution is verified; remote CI execution has not been verified. The application is a local research pipeline with a published static report.

@pytest.mark.parametrize("fault", ["negative", "missing", "infinite", "conflict", "gap", "weights", "unknown"])
def test_reject_bad_inputs(inputs, fault):
    prices, holdings, securities, _ = inputs
    if fault == "negative":
        prices.loc[0, "adjusted_price"] = -1
    elif fault == "missing":
        prices.loc[0, "volume"] = np.nan
    elif fault == "infinite":
        prices.loc[0, "adjusted_price"] = np.inf
    elif fault == "conflict":
        prices = pd.concat([prices, prices.iloc[:1].assign(adjusted_price=999)])
    elif fault == "gap":
        prices = prices.iloc[1:]
    elif fault == "weights":
        holdings.loc[0, "target_weight"] = 0.8
    elif fault == "unknown":
        holdings.loc[0, "ticker"] = "UNKNOWN"
    with pytest.raises(ValueError):
        clean_inputs(prices, holdings, securities)

06 / Historical results

Higher returns came with different risks.

The historical comparison measures how allocation rules changed returns, volatility and drawdowns after modeled trading costs. Every strategy begins with the same capital and is evaluated over the same dates.

  • Growth: 27.80% annualized return, 48.72% maximum drawdown.

    A 65% technology target produced the highest historical return and volatility. The large peak-to-trough loss matters as much as the ending value.

  • Balanced: the highest sample Sharpe ratio, 0.97.

    Its 19.12% annualized return exceeded XIC's 16.22%, with similar volatility and a smaller maximum drawdown. This is an observed comparison, not evidence of persistent alpha.

  • Low volatility: 15.29% realized annualized volatility.

    The lowest among the four constructed portfolios, compared with 16.37% for XIC. Inverse-volatility weighting is a heuristic; it does not solve for minimum portfolio variance.

  • One comparison, several objectives.

    Growth leads on historical return; Balanced leads on sample Sharpe; Low Volatility has the smallest realized volatility among the constructed portfolios. Each measure answers a different investment question.

How the scenarios are calculated

Python and NumPy resample complete 20-session blocks from aligned historical net portfolio returns, using the same block selections for all four portfolios and XIC. Each of 5,000 paths compounds 1,260 modeled returns from CAD 100,000. The table, downloadable CSVs and SQL mart share this equal-capital basis. The secondary continuation multiplies each path by its final historical NAV divided by $100,000. Time coordinates span exactly five calendar years; they are not an exchange trading calendar. Historical rebalancing costs are embedded in the sampled returns, rather than recalculated as future trades.

What this result supports: a comparison under a historical-repeat assumption. The sample contains unusually strong equity growth, so large median values and low loss frequencies must not be treated as reliable forecasts. Resampling changes the sequence; it does not independently estimate future expected returns. Unseen crises, changing valuations, parameter uncertainty, inflation and taxes are not modeled. There is no claim that these five-year ranges have been validated out of sample.

08 / Limitations

What the evidence establishes, and what remains open.

The system demonstrates portfolio accounting, reproducible ETL, relational reporting and reproducible scenario analysis. The reported return and risk differences apply to this selected historical sample.

Current limitations

  • Today's selected stock universe introduces survivorship and selection bias.
  • Adjusted history can be revised; it is not institutional point-in-time data.
  • Sector exposures differ materially from the benchmark.
  • No FX, taxes, delisted securities or explicit dividend cash ledger.
  • A constant risk-free rate and flat transaction-cost assumption.
  • Shared missing dates need an exchange calendar to detect.
  • Database publication is atomic; CSV and HTML exports are not a single transaction.

Priorities for the next research iteration

  1. Add a trading calendar and stronger data-coverage auditing.
  2. Evaluate alternative lookbacks, cost levels and sector-matched benchmarks.
  3. Test scenarios under explicit adverse regimes and alternative historical sampling windows.
  4. Assess five-year scenario calibration as independent outcome data becomes available.
  5. Introduce point-in-time universes, uncertainty estimates and versioned artifact publication.

Python, pandas, NumPy, SQLite, Plotly, matplotlib and Jupyter support the portfolio analysis presented here. MATLAB and portfolio optimization belong to the separate ETF portfolio research project.

09 / Lessons & quant role

What did we solve, and how can the results inform portfolio choices?

We turned a broad investment question into a repeatable comparison: given the same starting capital, how do different allocation rules change growth, volatility and losses? The pipeline produces evidence that an investment team can inspect before choosing an allocation or changing its risk limits.

Decision support and trust

Clients and stakeholders entrust investment teams with substantial capital. Whether performance is positive or negative, they need to understand what changed, where the gains or losses occurred, and the evidence behind the team's explanation. Unexplained results can weaken confidence even when returns are strong.

This project supports that accountability through validated inputs, explicit allocation rules, transaction-cost accounting, historical drawdowns, and reproducible scenario analysis. These records let a reviewer trace reported results back to the data, assumptions, and calculations, inspect portfolio exposures, and investigate unexpected outcomes.

For investment teams responsible for millions or billions, that transparency helps clients and stakeholders challenge assumptions and understand the risks being taken. A quantitative developer contributes to this trust by building calculations that can be checked, preserving the evidence behind results, and communicating model limitations clearly. The pipeline provides a foundation for that investigation; explaining precisely how much each holding or sector contributed would require a dedicated performance-attribution analysis.

1. What the portfolio comparison taught us

Growth delivered the highest historical return and the highest median outcome under the current scenario assumptions. Its technology concentration also exposed it to much deeper losses. Balanced had the highest historical Sharpe ratio, meaning it earned the most excess return per unit of volatility in this sample. Low Volatility achieved the lowest historical volatility among the four portfolios, although it still holds equities and can lose capital.

Income shows why portfolio names need to be tested against actual holdings and results: emphasizing banks, utilities and energy does not guarantee lower risk or a better total return. This study uses adjusted prices to approximate reinvested dividends; a separate cash-distribution analysis would be needed to judge whether it meets a spending-income objective.

2. How the future scenarios help a decision

The five-year model asks what could happen if blocks of past returns occurred again in different sequences. With equal investments and shared sampled market periods, we can compare ending wealth, losses of principal and the largest falls along each path.

Growth's median maximum drawdown is 33.5%, versus 20.3% for Balanced. Growth falls more than 20% below the initial investment in 24.2% of paths, versus 8.8% for Balanced. Growth also finishes behind Balanced in 19.3% of matched paths. At the 5th percentile of the Growth-minus-Balanced difference, Growth finishes $50,893 behind; 5% of differences are worse. These are frequencies within the simulation, conditional on its assumptions.

3. How an investment team could use the evidence

First define the objective: long-term growth, steadier performance, cash income or performance relative to XIC. Then specify the investment horizon, withdrawal needs, acceptable losses and sector limits. Compare the portfolios against those requirements using both historical results and simulated downside.

For example, if technology concentration or the potential interim losses are unacceptable, the team could test a lower technology weight and rerun the analysis to measure the change in return and risk. The revised allocation would need its own validation. A high historical return alone does not establish that a portfolio meets the objective.

4. What we learned about the model itself

The historical sample strongly influences the projected outcomes. Repeating a period of unusually strong equity growth can produce optimistic five-year medians. The model helps identify tradeoffs and assumptions to challenge; it does not establish which portfolio will win over the next five years.

A useful next step is to rerun the scenarios with different historical windows and explicit adverse assumptions. If an allocation looks attractive only under one set of assumptions, that dependence should inform the investment decision.

How this connects to a quantitative developer role

The quantitative developer's contribution is to make an investment idea measurable and repeatable. Here, that means using Python and pandas to validate financial data, implementing return, cost and risk calculations, using SQL to organize and reconcile results, and applying statistical methods to scenario distributions and downside comparisons.

The engineering controls matter to the investment conclusion: previous-close weights prevent today's return from influencing the allocation that earns it; initial-window calibration prevents future prices from changing the starting Low Volatility weights; reconciliation and automated tests catch accounting errors. Documenting the remaining selection bias and scenario assumptions makes the limits of the evidence visible.

This gives researchers and portfolio managers a practical workflow: propose an allocation, run a consistent comparison, inspect the risk and assumptions, and validate changes before relying on them. The project demonstrates how financial mathematics, statistical judgment and software engineering work together to support portfolio decisions.

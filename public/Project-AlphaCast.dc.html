AlphaCast

A systematic equity research application for testing whether trailing price and volume information can rank securities by their sector-relative performance over the next 20 trading sessions.

Project question

Can a model rank future relative winners without seeing the future?

AlphaCast is built around ranking, not pretending to know an exact future price. Each score is evaluated against the realized sector-relative return of a security, then compared with a simple momentum baseline under the same walk-forward rules.

Implemented research workflow

Evidence and risk controls in one reproducible run.

Implemented

  • Yahoo Finance ingestion with a transparent starter universe, plus a deterministic test panel
  • Trailing momentum, volatility, drawdown, moving-average, liquidity, market-relative, and sector-relative features
  • 20-session sector-relative excess-return target
  • Expanding-window folds with a 20-session embargo
  • Momentum, Ridge, Elastic Net, and Random Forest rankings
  • Rank IC, Q1-minus-Q5 spread, turnover, costs, portfolio paths, recent model health, and regime diagnostics
  • FastAPI dashboard, command-line JSON runs, automated tests, and Render deployment configuration

Deliberately not claimed

  • No price targets, trading recommendation, or claim of established alpha
  • No point-in-time fundamental or institutional market-data history
  • No delisting returns, borrow costs, taxes, bid/ask spreads, or execution-quality model
  • No production portfolio optimizer or live order routing
  • No conclusion based only on the strongest historical model result
Why the controls matter: each feature is known at the decision close, the forward label begins after it, and the training set stops 20 sessions before each evaluation. The dashboard makes model deterioration and changing market regimes visible instead of hiding them inside a single backtest average.

Next research iteration

Strengthen the data before expanding the claim.

The next phase is point-in-time constituent and fundamental data, realistic execution assumptions, capacity and sector constraints, and independent out-of-sample validation. Every addition should pass through the same chronological validation gate before it earns a stronger conclusion.
